name: Knowing God fidelity
description: Scope and integration decisions for the approved full Knowing God source feature.
---

Knowing God is a faithful integration of the supplied full source feature, not a new interpretation, sample or document-only reconstruction. Preserve the curated Scripture corpus, source identifiers, attributions, browser-local preference/study-list compatibility and complete introduction content.

**Why:** The user approved “Yes—add the full feature” for the uploaded replication source. Its curated corrections and relationships cannot be reproduced by simply extracting the original book again.

**How to apply:** Keep source corpus checksums meaningful when updating the interface. Do not regenerate or replace approved text as an incidental part of a UI change. The NET corpus belongs to the feature itself and must not acquire a runtime dependency on Bible.org or the original site.

All product navigation must stay within Follow. Knowing God must use Follow's own header and navigation, not the source JO EQUIP header or links to the source application. Preserve the warm reading surfaces and the existing framework.

**Why:** The user corrected navigation leaving the preview: “this whole project I'm having you create should stay within Follow.”

**How to apply:** Use existing Follow routes for menus and related resources. Supplemental Scripture links must open Follow's Bible reader, not an outside Bible website. Preserve attribution wording without using it to navigate away. Do not infer permission to link to the original application from a replication source.

The shared header brand should be the JO symbol followed by “JO FOLLOW,” matching the EQUIP project's treatment rather than the JESUSONLINE wordmark.

**Why:** The user requested: “Perhaps we should have the logo say 'JO FOLLOW' instead of JESUSONLINE like we did on the equip project.”

**How to apply:** Keep this branding consistent across Follow's shared header, including Knowing God pages.

Knowing God search results should load in the main window while someone is typing, not in the sidebar. Put matching titles first, followed by reference and content matches, as in Promises.

**Why:** The user requested main-window results, then asked to apply the same title-first search behavior as Promises.

**How to apply:** Keep live results in the primary reading area and all title hits ahead of non-title hits. Search coverage should not depend on which topics the reader has already visited.
